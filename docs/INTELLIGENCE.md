# Personal Purchase Intelligence and secondary merchant views

## Customer-first continuation

**New customer increment — under integrated verification, not shipped.** `/insights` is the customer destination in **Home / Purchases / Insights / Documents**. Its in-progress implementation reuses pinned AG Studio 3.0.0, the data engine, semantic theming, custom-widget registration and official Agent Framework; no customer needs a merchant workspace. The legacy `/merchant/intelligence` remains secondary and is not deleted. Its historical evidence below is not acceptance of new customer behavior.

The three views are **My Purchases**, **Documents & Care**, and **Price Adjustments**. Native Studio grid, category chart and count KPI query one saved-purchase source; custom widgets join only application-validated source records, care/attention availability and adjustment case IDs. Purchase rows are deduplicated, fixed-scope and bounded to the newest 100 Twins. Reference placeholder prices are null, not free goods; samples do not become verified spending. An independently verified refund is separate from a proposal, approval, pending result or illustration. Underlying documents preserve their own provenance, even when their purchase is Sandbox-verified.

CareOS uses a separate customer presentation planner/conversation under the existing Studio capability. The custom runner executes built-in schema/page inspection and bounded custom presentation tools. Required acceptance is actual execution plus exact target page/configuration, selection, widget/layout and data-engine postconditions—not a successful event alone. Fresh custom-widget queries, native counts/grid/render completion and stable execution scope are checked independently of optional SDK design diagnostics. No financial, merchant approval, arbitrary query or network tool is provided. Broad regressions use injected responses; useful genuine Sol Medium calls are authorized within the existing actually unexpired session/remaining accounting, checked before each call. No paid fallback, new allowance/session, renewal or usage reset is authorized.

Layouts are browser-local, versioned and reconstructed from known widget definitions and validated positions. Chart selections and source drill-down must remain consistent; unavailable dependencies do not turn into empty-result assurances. Interrupted planning retains the original request envelope. Saved-result GET recovery does not repeat inference or automatically execute a plan; explicit **Apply saved view** is required. **Acceptance checkpoint:** local unit/database/browser, injected Sol/recovery and **5/5 actual private customer Sol/SDK tasks** pass with separate evidence in [STATUS](STATUS.md) and the [verification ledger](evidence/CUSTOMER-INSIGHTS.md). ## Historical merchant workspace contract

### Scope and provenance

`/merchant/intelligence` is a public, read-only commerce workspace. Default data comes from the Guardian projection: at most the 500 newest cases. All-record case/verified totals are explicitly separate and never filtered as though they described the detail window. Illustrative scenarios are an explicit separate selection, never inserted into application financial tables. An illustrative completed amount is not a PayPal refund.

Three widgets share validated facts: **Value Recovery**, **Adjustment Status**, **Evidence & Freshness**. Counts distinguish proposed/approved/provider-pending/unresolved/verified/closed. Empty records never become illustrations. No financial tools, arbitrary SQL/URLs or merchant mutation. Sol Medium subscription planning and actual browser tool execution are now privately verified; paid API/public licensing remain separate. [Actual results](evidence/SUBSCRIPTION-QUALITY.md).

When the optional Studio workbench opens, the semantic summary is available through an accessible disclosure rather than stacking two full dashboards on a mobile screen. Dataset/provenance/filter-scope labels stay visible. Closing the workbench reopens the summary. This presentation preference grants no commerce authority and does not remount checkout.

### Actual AG Studio, local evaluation only

Current evaluation gate additionally requires **`AG_STUDIO_LOCAL_EVALUATION_ENABLED=true`**, exact local `APP_ORIGIN` and matching request Host. Host alone cannot enable it. Default is off. For example, `APP_ORIGIN=http://localhost:3000 AG_STUDIO_LOCAL_EVALUATION_ENABLED=true pnpm dev` enables permitted local evaluation, not public deployment. The initial mobile layout stacks custom widgets; saved layout remains presentation only.

Exact-pinned `ag-studio` / `ag-studio-react` **3.0.0**. Published React peer range includes 19; documented TypeScript minimum is 5.8.3 (application uses 5.9.3). Matched transitive Grid/Charts versions are lockfile-pinned. **At the historical merchant-only checkpoint**, Studio was loaded dynamically only when opened and customer routes did not import its runtime. The new customer `/insights` implementation now has its own gated/dynamically loaded Studio runtime; the old no-customer-import statement does not apply to it. No Google Fonts loading. Theme uses the existing light/dark identity.

The real React component hosts the three application widgets, which query the Studio data engine. Stage controls now share one application-owned page selection translated through immutable Studio state APIs; independent hidden stage cross-filters no longer intersect an already filtered input dataset. Widget-specific verified summaries further restrict the page selection, while labeled all-record totals remain unfiltered. Layout editing changes browser presentation only. Saving/restoring validates the three known widget positions, bounded dimensions and no extra keys. Layout is local to dataset mode; it confers no authorization.

The vendor explicitly permits **local testing without a license**, with its original watermark/warnings intact. Workbench access is limited to local hostnames as a UX guard, not a security boundary or a substitute license. Public deployment is not enabled. No owner account/trial has been activated, no key has been obtained, and coverage through **December 15, 2026** is **not established**. Owner action is needed to obtain an appropriate trial/extension or license before relying on it for public judging. A 45-day trial started in October can expire too soon. The historical merchant custom widgets did not embed standalone Grid/Charts Enterprise instances; that observation does **not** establish license coverage for the new customer native grid/chart/KPI or AI feature set. Verify the actual Studio/native/Pro/AI terms and any separate product requirements before public use; do not assume either coverage or an additional license from the old widget architecture.
