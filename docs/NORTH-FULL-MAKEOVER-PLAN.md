### 3.1 One task/result contract

Use a versioned, strict application contract for **operation, scope, normalized filters, requested format, date reference/timezone, result identity, coverage and provenance**. Server-resolved records/links and computed amounts are authoritative; the model may propose bounded intent/presentation, not SQL, arbitrary URLs, amounts, permission or financial operations.

The result retains its query fingerprint, observation/snapshot identity, matching record identities, exclusions and computed facts. Format changes reuse that **owned saved result**, not invented model memory. A changed dataset is labeled stale/refreshed explicitly; an old answer is never relabeled to the new product or silently recomputed under different filters. Persist additive compatible metadata in existing JSON storage where safe; a genuinely necessary application migration requires separate approval, not a schema-push workaround.

### 3.2 Search all available saved records honestly

- “All purchases” means all **server-available saved purchases in the fixed fictional scope**, never universal PayPal account history or a merchant dataset.
- The existing projection is the newest **100 Twins**. Distinguish that loaded/native display window from query coverage. For more saved records, use bounded fixed-scope pagination/aggregation and stable result coverage rather than silently reporting newest-100 results as complete-library totals. If complete coverage cannot be established, label partial results and do not claim a global total.
- Resolve dates/categories/search/receipt/document/care predicates before forcing purchase selection. Clarify only real ambiguity, such as several dated matches for a requested individual receipt.
- Relative dates use a captured reference date and explicit timezone: **last month = previous complete calendar month; last three months = rolling three calendar months through the reference date**. Echo exact inclusive boundaries. Preserve date-only purchase dates; test month ends, leap years and timezone edges.
- Use a reviewed alias map, including **Electronics → Audio + Computing**, shown to the user. Unknown categories or ambiguous periods get one concise correction/clarification, not invented taxonomy.
- Distinguish an attached receipt from a policy/care card. Resolve each link from its exact validated Twin/document association.

### 3.3 Money and analytic truth

- Calculate on the server using **integer minor units**, recorded purchase snapshots and supported currency. Catalog prices are not amounts paid; no model-calculated totals become trusted facts.
- Keep **Sample purchase value** and **Verified Sandbox purchase value** separate in totals, comparisons, native series/KPIs and drill-downs. Neither is real personal spending.
- Count unavailable/unpriced/reference items explicitly and exclude them from monetary sums. A reference zero is not free goods. Preserve true zero, zero matches and unavailable evidence as different states.
- Deduplicate by validated purchase/payment identity, not product name; retain legitimate repeated purchases. Reject conflicting evidence rather than choosing convenient values.
- Compare like periods with explicit dates, counts, coverage and per-provenance denominators. Handle empty/zero prior periods without invented percentage growth. Describe observed patterns, not causal explanations or statistically unsupported trends.
- Keep original value and independently verified recorded adjustments separate; pending/proposed refunds do not reduce totals. Existing financial records are read-only; no new payment/refund is required.
- Every number offers **View purchases** with the exact contributing record set and visible exclusions. Totals, bullets, cards, grids and charts use the same normalized result/query scope, even when the row display is paginated.
