# ADR 0008: Local Studio tools and source-backed, nonfinancial aftercare

**Status:** Accepted for the approved continuation; external runtime/licensing gates remain separate.

## Decisions

- Keep the Next.js modular monolith and original payment/Guardian services unchanged. Add source/discovery schemas through reviewed migrations; preserve all existing records and separate new nonfinancial evidence/history.
- Use actual exact-pinned AG Studio 3.0.0, three custom React widgets, its data engine/cross-filtering and real Agent Framework tool execution. Local evaluation is permitted without a key, with vendor notices retained. Explicit local configuration does not establish commercial/public license coverage. Obtain owner coverage through judging before deployment.
- Keep recorded and illustrative datasets separate. Dashboard filters describe bounded facts, never falsely filtered all-record totals. Browser-local report changes grant no merchant authority. The initial runner is visibly scripted, with a bounded allowlisted tool vocabulary and a separately validated future planner seam; genuine model transport/inference is not claimed.
- Start Recall Guardian with one actually retrieved historical official CPSC notice, not a pretend comprehensive feed. Pin content/rules, validate official destinations and exact identifiers, preserve missing/physical identity uncertainty, append source/assessment revisions, and retain last-known evidence on failed checks. A no-match is not an all-clear. A coding-agent source review is not a human safety certification.
- Build Channel3 against documented REST contracts, with fixture defaults, private bounded search, stable persistent credit reservations, a writer unable to modify trusted records, curated product IDs and freshly retrieved offers. Unknown categories/conditions, unsafe links and stale/malformed prices are not buying recommendations. No account, paid overage, MPP fallback or automatic purchase is introduced.
- Expand deterministic/fixture CareOS evaluations rather than claim hosted-model performance. Safety/status/calculation remain deterministic. Runtime inference, actual Channel3 acceptance and the controlled PayPal refund require separate approval/evidence.

## Consequences

Meaningful sponsor tooling and reproducible source-backed UX can be developed without asking the owner to run each increment. This does not eliminate final actual-provider, licensing, live-AI, human usability or public-delivery gates. Keep the PayPal purchase/verified-adjustment story central; neither sponsor count nor fixture polish establishes submission eligibility or a prize result.
